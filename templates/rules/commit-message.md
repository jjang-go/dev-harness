# 커밋 메시지 규칙

커밋 메시지는 diff가 말해 주지 않는 변경의 이유를 남기는 곳이다. 이후 이력을 읽는 사람과 에이전트가 의도를 추측하지 않도록 아래 규칙을 따른다.

## 형식

```
<타입>: <제목>

<본문>

<이슈 참조>
```

- 제목과 본문 사이, 본문과 이슈 참조 사이에 빈 줄을 둔다.
- 언어는 한국어로 통일한다. 타입 키워드만 영어를 그대로 쓴다.

## 제목

- 타입 접두어를 붙인다: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `style`, `build`, `ci`
- 접두어를 뺀 설명은 한글 25자 내외로 쓰고, 서술 간결체로 쓰며 마침표를 붙이지 않는다.
- 소스를 보지 않아도 변경을 알 수 있게 구체적으로 쓴다. "수정", "변경", "작업 중" 같은 맥락 없는 표현은 쓰지 않는다.
  - 나쁨: `fix: 버그 수정`
  - 좋음: `fix: 만료 토큰 갱신 시 세션 끊김 방지`
- "이 커밋은", "이번 PR에서" 같은 표현과 1인칭("수정했습니다")은 쓰지 않는다.

## 본문

본문은 `[대괄호]` 소제목으로 나눈다. `#`로 시작하는 줄은 git이 주석으로 지우므로 쓰지 않는다. 소제목은 아래 순서를 지키고, 해당 내용이 없는 소제목은 통째로 생략한다.

- `[배경]`: 왜 바꿔야 했는지. 바꾸기 전의 문제와 그 영향을 쓴다. 본문이 있으면 이 소제목은 항상 둔다.
- `[변경]`: 무엇을 어떻게 바꿨는지. diff를 그대로 옮기지 말고 의도가 드러나는 단위로 요약한다.
- `[영향]`: 부작용, 직관과 다른 결과, 호환성처럼 변경이 미치는 범위와 주의점.
- `[검증]`: 무엇을 어떻게 확인했는지. 확인하지 않은 부분이 있으면 그렇게 적는다.

```
fix: 만료 토큰 갱신 시 세션 끊김 방지

[배경]
인증 서버가 토큰 만료 시 상태 코드를 일관되게 주지 않아
사용자 세션이 조용히 끊겼다.

[변경]
- 4xx 응답을 인터셉터에서 잡아 인라인 갱신
- 갱신 실패 시 로그인 화면으로 이동

[영향]
- 모든 4xx를 갱신 대상으로 보므로 인증 외 오류도 한 번 재시도된다.

[검증]
- 만료 토큰 1회 갱신 (단위 테스트)
- 갱신 실패 경로 (수동 확인)

Resolves: #123
```

- 한 줄은 72자 안팎에서 줄바꿈한다. 목록은 `-`를 쓴다.
- 사소한 변경은 본문과 소제목을 모두 생략하고 제목만 쓴다.

## 이슈 참조

- 이슈가 있을 때만 본문 맨 아래에 트레일러로 적는다.
  ```
  Resolves: #123
  See also: #456, #789
  ```

## 커밋 단위

- 하나의 커밋에는 하나의 의도만 담는다. 서로 다른 이유의 변경은 나눈다.
- 공유 브랜치나 이미 공개한 커밋은 rebase나 squash로 이력을 다시 쓰지 않는다. 브랜치 전략이 정한 PR(MR) squash 병합은 대상 브랜치에 새 커밋을 만드는 것이므로 여기에 해당하지 않는다.
