# README 작성 규칙

README는 프로젝트의 첫인상이자 사용 설명서다. 없거나 낡으면 구조와 사용법을 파악하는 데 시간이 들고 유지보수가 어려워지므로 아래 규칙을 따른다.

## 작성 원칙

1. **최신 상태를 유지한다.** 내 변경이 동작, 설치 절차, 구조를 바꿔 README를 낡게 만들면 README 수정을 같은 변경에 포함한다. 변경과 무관하게 어긋난 부분은 사용자에게 알리고, 요청이 있을 때만 고친다. 코드와 어긋난 README는 없는 것보다 해롭다.
2. **간결하되 필요한 정보는 빠뜨리지 않는다.** 분량을 줄이기 위해 필수 항목을 생략하지 않는다.
3. **길어지면 분리한다.** 주제별로 별도 문서를 만들고 README에서 링크로 연결한다. 한 문서에 모두 넣지 않는다.

## 필수 항목

- **목적과 주요 기능:** 이 프로젝트가 왜 존재하고 어떤 문제를 해결하는지
- **사전 요구사항:** 실행 환경, 필요한 도구와 라이브러리, 버전
- **설치 방법:** 처음 보는 사람이 그대로 따라 할 수 있는 단계별 절차와 환경 설정
- **사용 예시:** 복사해서 실행할 수 있는 구체적인 예
- **라이선스:** 사용, 수정, 배포에 대한 권리와 제한. 외부에 공개하거나 배포하는 프로젝트만 해당한다. 내부에서만 쓰는 프로젝트는 생략한다.

## 권장 항목

- **자주 발생하는 문제와 해결 방법**
- **지원 창구:** 유지 관리자나 담당자와 소통하는 방법
- **변경 로그:** 주요 업데이트 내역 (분량이 많으면 별도 파일로 두고 링크)
- **추가 학습 자료와 문서 링크**

## 점검

README를 작성하거나 수정할 때 위 필수 항목이 모두 있는지, 설치·사용 예시가 현재 코드와 일치하는지 확인한다.
