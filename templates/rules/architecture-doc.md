# 아키텍처 문서 규칙

프로젝트 루트의 `ARCHITECTURE.md`는 코드 구조를 알려 주는 지도다. 코드를 일일이 뒤지기 전에 이 지도부터 본다.

## 읽기

- 어디를 고쳐야 할지 찾거나 구조를 파악해야 하면, 코드를 탐색하기 전에 `ARCHITECTURE.md`의 코드맵을 먼저 읽는다.
- 코드맵의 이름(모듈, 파일, 타입)은 링크가 아니라 검색어다. 이름으로 코드를 검색해 위치를 찾는다.
- 파일이 없으면 이 규칙은 건너뛰고 일반적인 방법으로 탐색한다.
- 문서와 코드가 어긋나면 코드를 기준으로 삼고, 어긋난 사실을 사용자에게 알린다. 지금 하는 변경 때문에 어긋난 것이 아니라면 사용자가 요청할 때만 문서를 고친다.

## 갱신

- 내 변경이 모듈을 추가, 삭제, 이동하거나 책임을 바꿔 문서를 낡게 만들면 같은 변경에서 `ARCHITECTURE.md`를 함께 고친다.
- 내 변경이 계층과 경계, 불변조건을 바꿀 때도 함께 고친다.
- 파일 하나를 고치는 정도의 변경은 갱신하지 않는다. 이 문서는 자주 바뀌지 않는 내용만 담는다.

## 작성

- 짧게 쓴다. 상세 동작은 쓰지 않고 코드 주석이나 별도 문서에 맡긴다.
- 파일, 모듈, 타입은 이름으로 적고 링크를 걸지 않는다.
- 문서를 점검하면 맨 위 "마지막 점검" 날짜를 갱신한다.
